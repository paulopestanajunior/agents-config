# Documentation Workflow

1. Define the audience and documentation type: README, architecture doc, ADR,
   RFC, runbook, API doc, integration guide, onboarding doc, troubleshooting
   guide, or migration guide.
2. Inspect existing docs, code, configuration, scripts, tests, and observed
   behavior relevant to the topic.
3. Identify facts, inferences, hypotheses, gaps, and inconsistencies. When
   sources disagree, record the disagreement instead of silently choosing one.
4. Preserve official terminology, command names, product names, API names, and
   domain terms.
5. Draft the document with explicit prerequisites, commands, paths, ownership,
   failure modes, and validation steps where relevant.
6. Cross-check examples, commands, links, paths, and diagrams against the
   repository.
7. State any remaining unknowns or assumptions.
8. Validate the final doc against the intended audience's workflow.
